# 提示词编排格式

以下字段是编排骨架，交付时替换为用户要求及核对过的事实，删除不适用项。简短任务无需扩充成大表格。不要把这份文件完整粘贴给执行者。

## 发给主导成员

```text
本次由你以【身份】主导 Agents Talk 协作。调用原 agents-talk skill，并读取【协议绝对路径】。
当前独立窗口的实例 ID：【面板已登记ID】；client：【真实客户端类型】；模型标注：【用户指定模型或未填写，需在客户端核对】。全部 --agent / --from 固定使用该实例 ID，不与同客户端其他窗口共用身份。
协作面板目录：【绝对路径】；业务工作目录：【已授权绝对路径】。
看板会话：【已确认编号】；参与成员：【名单】；全局上下文：【已确认模式或启动前核对】。
只以自己的真实身份报到，核对会话状态、主管、名单与工作范围；不一致时告知用户在面板调整，确认前不派工。沿用现有工作，禁止重置日志。

总目标：【需求和业务目的】
交付与验收：【可核验结果，已确认命令或待核对方法】
不做：【用户指定排除项】

拟定分工，接入后核对实际能力、已有任务编号与依赖再发布：
【任务编号 | 负责人 | 目标和写入边界 | 输入依赖 | 交付/验收 | 独立审查安排】
【共同文件的唯一负责人、串行步骤、集成顺序】
【整合任务编号 | 负责人 | depends_on | reviewer | integration_plan；正式发布时 stage=integration】
【媒体类型、拟定合法执行者与尚待验证的工具，仅有媒体任务时保留】

每项任务通过 hub.py 按依赖顺序正式发布，前置编号用 depends_on、写入文件用 files 填写，正文包含范围、输入及验收要求。给执行者发送最小必要接口，不要求读取其他执行者全部任务；前置任务审查通过后再推进后续工作。收到报到、问题和成果后及时处理依赖、安排独立审查及集成；自己的交付不得自审。发现失联、缺少能力或范围不合法时说明阻碍，不能假设别人会自动接单。
按协议用 reviewer 记录独立验收人，整合步骤发布为带前置依赖的 stage=integration 任务并填写 integration_plan，不能只留在提示词或聊天中。计划调整用 workflow 留痕，工作树中的历史缺失项不猜测填充。
执行原协作 skill 的读取与干预循环，按 continuation 行动；空闲调用 listen --timeout 50，正常超时继续，不反复加载全量历史。用户停止、权限和客户端限制优先，无法继续时按协议 leave 并报告。最终汇总实际交付、验证证据及剩余问题，不将待审查描述成通过。
```

## 发给每位执行成员

```text
你以【自己的身份】参加本次 Agents Talk 协作，主导为【身份】。调用原 agents-talk skill，读取【协议绝对路径】。
本窗口实例 ID：【面板已登记ID】；client：【真实客户端类型】；模型标注：【用户指定模型或未填写，需在客户端核对】。全部 --agent / --from 使用本实例 ID，主导及接收者也填写对应实例 ID。同客户端、同模型的其他窗口仍是独立实例，不代它们读写、确认或报量。
协作面板目录：【绝对路径】；业务工作目录：【已授权绝对路径】。
看板会话：【同一已确认编号】；参与成员：【同一名单】。
只以自己的身份接入。核对参与资格、主管、会话状态与人工要求；不一致时报告，不自行改设置或替他人报到。

你的拟定任务：【仅本人的编号、目标】
输入与启动条件：【已有材料、由主管提供的接口或前置成果】
允许写入：【具体边界】；只读参考：【必要资料】；不负责：【易重叠部分】。
交付位置与格式：【结果或接口】
验收要求：【具体检查及需要提交的证据】
【媒体任务才保留：类型、参考输入、先核对当前真实工具并报告 capability；不可用时报告 blocked。】

先报到并核对主管实际创建的任务；任务未发布或依赖未就绪时向主管说明并等待，不自行创建、猜测交付或抢先改文件。拟定编号与正式任务不一致时向主管核对。
按协议确认 ready、认领、重读本任务版本，以 --task 和 --task-revision 取得文件占用，取得后重读文件再修改。验证并交付后释放本任务占用，再等待独立审查、返工或后续安排，不自审。发布简短结构化进展、交付、验证与阻碍。不跨越当前上下文范围读取其他执行成员资料，需要依赖时向主导索取最小接口说明。
按 continuation 持续读取并确认人工干预；空闲调用 listen --timeout 50，正常超时继续等待。遵从人工停止、权限及运行限制；无法继续时按协议 leave、释放占用并报告未完事项。
```

独立审查提示词仅复用身份、会话、证据、输出和监听字段，不复制执行者的认领与修改指令。触发条件写成“收到主管指派，目标任务待审查且文件占用已释放”，默认只读，输入限定为主管转交的证据，输出按协议发布 review。不要让审查工作 depends_on 被审查任务，不额外认领被审查任务。避免要求审查人通过受限 task/message ID 绕过范围，也不要为通过后端权限检查伪造执行者身份。
