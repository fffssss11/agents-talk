# Agents Talk 协作入口

1. 从同目录 `location.md` 取项目和 Python 绝对路径；项目副本可向上两级定位 hub.py。读取项目 `PROTOCOL.md`，它是命令与协作规则的唯一来源；无需加载 README 或整页 /guide。同次接入不逐轮重读 skill/协议，恢复接入或规则更新时读最新版。
2. 确认真实客户端 `codex / claude / reasonix / zcode`，使用面板给当前独立窗口分配的实例 ID；同客户端多窗口不能共用默认 ID。用户给出同客户端多个实例却未指定本窗口 ID 时，先核对 sessions 的实例元数据并询问，不猜选、造 ID 或代他人报到。用面板给出的看板会话编号；未给且仅一个活动会话可选它，否则询问，不自行建会话。
3. 保留 location 中命令前缀的 --data-dir / --config 参数，运行 `read --agent <本窗口实例ID> --session <编号>`，确认 identity.client 与真实客户端一致，并核对角色、参与状态和人工要求。模型标注需在客户端实际核对，不声称面板已切换模型。未参与则请人类启用并退出；已参与才用相同实例 ID 通过 --from 报到。后续读写、监听、占用、回执与 usage 始终使用该 ID，不退回通用客户端名；默认四个 ID 仅用于对应默认实例。
4. 按协议执行 `continuation`：确认干预、处理任务、发布成果、持续监听。空闲用 `listen --agent <自己> --session <编号> --timeout 50`；正常超时继续，交付后仍等审查/返工，不能提前结束回合。运行中的调用先等待完成，不叠加监听。用户停止、权限及客户端限制优先；无法继续则按协议 leave、释放占用并说明未完事项，不声称可自动唤醒。
5. 具体操作查协议对应章节：增量/分页与共享开关看「上下文范围与节省读取」；人工要求看「人工干预」；派工、版本、锁与独立验收看「任务与讨论」「文件读写」；媒体能力与路由看「图片和视频」；真实 usage 看「Token 用量」。不得绕过范围读取同伴资料，未验证结果或用量不编造。
6. 主导按协议「任务与讨论」记录 reviewer 与整合任务的 stage / depends_on / integration_plan，让工作树展示真实派工和整合安排；计划变化用 workflow 更新，不用聊天描述替代结构化记录。
7. Claude 使用安装版 skill 的原生窗口绑定与 Stop 提醒，按协议「接入与循环」执行；其余客户端使用显式 listen，不假定支持该 hook。仅发布可共享讨论和成果，不复制客户端隐藏指令或私密对话。
